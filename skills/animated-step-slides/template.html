Overview

Two paths through the same four parts

Cache miss

  • The CDN asks the app, the app reads the database
  • The answer is stored on the way back

Cache hit

  • The CDN answers by itself
  • The app and the database do nothing

Path 1

Cache miss

The first request for a page

browserGET /page
CDNedge cache
apprenders HTML
databasepages table
  1. The browser asks the CDN for /page
  2. The CDN has no copy, so it has to ask the app
  3. The app reads the page and its parts from the database, three queries
  4. The HTML goes back through the CDN, which keeps a copy

→ one step forward / ← back

latencyabout 300 ms cachestored for 5 min

Path 2

Cache hit

The same page within five minutes

databaseidle

  2. The app and the database are not touched

Summary

What to remember

  • A miss costs one round trip to the app and three queries
  • A hit never leaves the CDN
